# ADR 0003 — SQLite methodology persistence and exact decimal transport

Date: 2026-09-10. Status: implemented, pending Slice 4 approval.

## Context and decision

M6.2 Slice 4 requires the methodology registry skeleton and actual numeric persistence proof, while business entities belong to M6.3+. Use Prisma/client/SQLite adapter 7.10.0 with better-sqlite3 12.11.1 on the pinned Node 22 runtime. Follow the [Prisma v7 configuration and adapter guidance](https://docs.prisma.io/docs/guides/upgrade-prisma-orm/v7).

The initial migration contains only methodology_record. Camel-case application fields map to snake-case physical fields. Identity is the primary key; family/effective_date are indexed. Date-only and canonical UTC instant values remain validated TEXT, preserving their distinct semantics without JS Date conversion. Required metadata includes approval, configuration, governing-document and implementation references. These are lineage references, not verification of external documents or an approval workflow.

The port exposes append separately from lookup; no mutation endpoint exists. Repository validation protects writes and checks persisted records on reads. Duplicate identity maps to ConflictError; application requireMethodology maps a missing record to NotFoundError while nullable find retains its contract. Database triggers reject updates/deletes. Supported connections enable recursive triggers, preventing INSERT OR REPLACE from bypassing immutability. This is application integrity, not protection against an owner who directly rewrites the database file or disables triggers.

Prisma is confined to infrastructure and server composition. Generated code is treated as vendor code, ignored by source lint/Git, and regenerated by dependent scripts; imports into it remain subject to boundary enforcement. openPersistence exposes a registry and close lifecycle, never a raw client. The shell does not initialize persistence. Migrations run explicitly through the project-root-anchored CLI wrapper, not during startup.

## Exact representation

Use canonical decimal strings and SQLite TEXT for the early authoritative numeric transport proof. No Number/REAL conversion occurs. A test-only numeric_probe table demonstrates JSON serialization, parameterized Prisma write, independent connection read, SQLite typeof=text and exact string comparison. Whole VND, values beyond safe integer, fractional prices/rates, negative values and scale survive. BigInt rational arithmetic independently confirms an exact product with a fractional fee before/after persistence. This introduces no production financial columns, money arithmetic library or rounding policy. Future financial calculations must select exact arithmetic and field-specific units/ranges under their owning milestone.

## Storage and migration safety

Default storage is project data/vn30.sqlite, computed at runtime. Custom URLs require raw absolute local file paths, private parent/file permissions, and placement outside public/.next including resolved aliases. Existing content/permissions are never reset or changed. File checks assume a trusted local OS user; they are not a defense against concurrent privileged filesystem replacement. POSIX permissions are validated on macOS only.

Connections enable foreign keys, recursive triggers, a bounded busy timeout and DELETE journal mode. This slice supplies no backup/restore implementation or WAL copying guarantee. Tests allocate independent private temporary directories, override inherited targets, skip local environment files and clean up after disconnect. First migration has no previous supported schema; repeated deploy and reopen preserve records. FK relationship testing is N/A because no relationship exists.

## Dependency remediation and consequences

Initial audit found deepmerge-ts recursion DoS and two mysql2 advisories through Prisma CLI. Scoped pnpm overrides pin @prisma/config>deepmerge-ts to 8.0.0 and prisma>mysql2 to 3.23.1. The [deepmerge 8 release](https://github.com/RebeccaStevens/deepmerge-ts/releases/tag/v8.0.0) changes Map merging; this config uses plain records, and actual validate/generate/migrate/status tests cover the used CLI path. mysql2 is not a runtime adapter here. Revisit overrides when upstream dependencies are patched; do not silently remove them. Advisory references: [deepmerge](https://github.com/advisories/GHSA-ggr8-5vv4-36mx), [mysql2 high](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr), [mysql2 moderate](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3).

SQLite suits the approved local scope. Switching to PostgreSQL would require an explicit migration/data conversion and revisiting trigger semantics, not just a URL change. Native adapter availability and the security overrides are maintenance costs. Existing ESLint 9 lifecycle and transitive prebuild-install deprecation remain documented Minor issues.
