## Phase B — Ingest, Transform & Persist

Implement:

CaféF API / retained raw response
→ Immutable Raw Evidence
→ Identity & Hash Verification
→ RAW Close Extraction
→ Unit Conversion
→ Normalized Market Observation
→ Capability/Market Validation
→ Deterministic Replay
→ Governed Persistence
→ Valuation Consumption

Requirements:

- Reuse the existing CaféF normalizer and market-boundary domain contracts.
- Do not introduce a competing price calculation.
- Never use GiaDieuChinh as fallback.
- Preserve the original response, request identity, original units and hashes.
- Normalize thousand VND/share to VND/share using deterministic decimal arithmetic.
- Record ticker, exchange, trading date, session, provider, source version, policy version, normalization version and knownAt.
- Separate observed trading date from ingestion/availability time.
- Validate before marking a record as accepted.
- Use idempotent writes and atomic raw-to-normalized linkage.
- Prevent duplicate observations, partial acceptance and cross-ticker contamination.
- Do not overwrite existing immutable evidence.
- Keep unqualified records quarantined with exact failure reasons.
- Support deterministic reprocessing from retained raw bytes without refetching.
- Preserve current storage, accounting and portfolio boundaries.
- Do not invent source timestamps or silently treat later receipts as historically available.

If the existing system lacks a suitable governed normalized-market store, extend the smallest existing persistence boundary rather than creating a parallel database.

## Phase C — Automated Admission

Implement policy-driven qualification:

- Standing source policy must be explicitly authorized and version-bound.
- Adapter and schema must match the approved scope.
- Each observation must pass ticker, exchange, trading-date, raw-close, units, source-identity and hash checks.
- Trading-session and observation-time conventions must satisfy existing Market Boundary contracts.
- Replay must reproduce the normalized result from original evidence.
- Capability and Market acceptance must use actual existing lifecycle/authority contracts.
- Valuation consumption must reject records outside approved policy scope.

Automate routine acceptance only after all mandatory controls pass.

A failed or changed schema must suspend automatic admission for the affected scope.

No automatic approval of new provider versions or changed financial semantics.
