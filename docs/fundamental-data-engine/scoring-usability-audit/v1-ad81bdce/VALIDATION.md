# Validation

Run `python3 validate.py` in this versioned folder. It validates 690 unique rows/30×23, exact classifications, evidence pointers and source hashes, preserved research bindings, Decimal arithmetic, configured Master parity, required deliverables and captured protected-code/policy/financial JSON/database byte fingerprints and metadata for the other preexisting files. See `validation-results.json` for exact executed counts/results and `manifest.json` for canonical matrix/file hashes.

Reproduction: run `python3 build.py`, then `python3 augment.py`, then `python3 refine.py`, then `python3 validate.py` on the pinned baseline and unchanged retained sources. Build/augment write this audit folder only; validate reads repository sources/SQLite receipt, never production engines or providers. BASELINE_FINGERPRINTS.json records protected runtime/policy and retained financial JSON/database hashes captured during this docs-only audit; approved tracked inputs are also compared with HEAD git blobs. ARCHIVE_METADATA_BASELINE.json records size/mtime for preexisting tracked/data files. PDFs/media/archives are not comprehensively rehashed or re-extracted; metadata parity is a weaker check, not byte identity. No earlier source receipt was edited. Source pins protect approved P2.5/P2.6/sandbox and methods; original historical metadata stays historical.

Limits: source JSON/schema inspection and note term searches do not validate every OCR caption or certify full topic evidence. No PDF re-extraction, acquisition, full application suite, engine regression, live decision, accounting admission or formal independent analyst approval was executed. The static CAGR/action predicate witnesses prove inspected guard behavior, not end-to-end model acceptance. Existing legacy release/test failures are outside this docs-only audit; no whole-production PASS is claimed.

Initial metadata-only failure is preserved in validation-attempt-01.json: 1,427 timestamps differed by at most 120ns, no sizes changed, and the cryptographic checks passed. The corrected metadata check allows 1µs timestamp precision; byte hashes, source hashes, approved HEAD parity and database checks are unchanged. This is an audit-validator precision correction, not a source/baseline edit.

Executed validation: **131/131 checks PASS**, comprising 130 passing checks from the preserved completed full run and the one corrected metadata check rerun. Protected hashes: 1,594 files; source pins: 214; metadata inventory: 10,438 files. Original failure and the precision retest are both retained. No complete-engine/application test or independent human acceptance is claimed.

For the existing completed run, `python3 recheck-metadata.py` reproduces the isolated precision retest only, verifies unchanged critical audit input hashes against the original manifest, and retains the 130 previously passed checks.
