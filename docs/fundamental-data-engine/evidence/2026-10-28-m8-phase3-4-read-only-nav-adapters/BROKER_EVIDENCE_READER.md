# Immutable broker evidence reader

2026-10-28 · Phase3.4 SliceA · READ_ONLY_ADAPTERS_ONLY

Supported schema: **nav-broker-observations-v1**. It is an unapproved retained observation envelope, not a TCBS/PDF source contract, approval record or accepted financial mapping. The reader does not synthesize envelopes from existing raw captures. Positive reader validation uses explicitly synthetic envelopes; real TCBS/PDF decoding/account/asOf qualification remains unsupported and blocked pending separately authorized contracts. This limitation prevents silently accepting incompatible retained formats.

Server-supplied BrokerEvidencePinV1 binds evidence ID, exact relative path, SHA-256, byte length, schema, document ID/provider, account, portfolio and perimeter. Payload must match every identity; filename alone has no authority. No source namespace is qualified by being present in the file. Header preserves economic observedAt, retrievedAt, knownAt, optional publicationAt(null if unknown), currency. No fabricated publisher timestamp.

fields retain stable ID, original field caption/name, kind, exact decimal-string/null value, declared unit, exact unaccepted security ID/lifecycle where present and document reference/JSON pointer. A pointer must match the physical envelope field value and reference its exact document. These are envelope-byte provenance pointers, not a claim of original broker API/PDF lineage unless independently supplied/accepted in a later source contract. Value strings and numeric JSON lexemes are preserved losslessly by existing exactJson; 13th fractional digit is rejected, never rounded. Explicit null/missing/zero remain distinct. No semantic mapping based on caption equality, amounts, ticker or publisher reputation occurs.

Path/read contract: absolute canonical configured root; nonempty relative paths with no dot/dotdot/backslash/absolute component; realpath root and lstat each component reject symlinks/nonregular files. O_RDONLY|O_NOFOLLOW|O_NONBLOCK opens a bounded descriptor. Declared size and actual regular-file size must agree and fit limit(default1MB, hardmax4MB). Read at most size+1, compare descriptor size/device/inode/mtime/ctime and original/final path inode chain before returning, then verify exact SHA-256. Replacement after open, even identical new bytes, fails inode checks. No write/open-create, network or database API is used.

Only strict UTF-8 without BOM/NUL is accepted. Duplicate JSON keys, unsupported versions/fields/units/lifecycle, malformed sizes/hashes, mismatched account/document/perimeter, duplicate IDs/observation keys, conflicting values and future/inconsistent timestamps fail closed. Reject outcomes preserve parsed observations/conflict list when available, but never become usable accepted data. Missing files return safe reason without disclosing credentials/path errors.

OBSERVED means structurally read/integrity matched, accepted=false. BLOCKED returns reasons, conflicts and parsed evidence if safe. observedAt must exactly equal requestedT; retrieval<=knowledge<=K<=C and observation<=retrieval. No current-balance substitution or date-only midnight inference. A future document correction remains separate bytes/pins; no latest-wins selection.

Filesystem checks are defense in depth for a controlled local evidence root, not an OS sandbox or tamper-proof storage. Same-user/privileged attackers can control a process/filesystem; no authenticated authority is derived from these checks. The wrapper does not establish secure directory ownership/permissions or audit anchoring. Operational gates remain blocked.
