# Market Data Readiness Contract — PROPOSED, NOT APPROVED

A capability certificate is hash-bound to approved source contract, adapter/normalizer version, provider schema/template identity, security universe/venue coverage, freshness policy, exchange-calendar version, corporate-action rules and a retained validation corpus. It records issuer/provider authority separately from provenance transport. Existing financial APIs do not become authoritative market sources by being available. A controlled manual import can qualify only if the actual market-source evidence and its approved ingestion/retention/replay process qualify; a free-text source URL is insufficient.

| Requirement | Exact proposed minimum | Fail closed when |
| --- | --- | --- |
| Approved sources | Versioned approved source stack, purpose/venue/field allowlist, licensed/authorized capture path, effective/known-at dates, explicit fallback precedence | Source unapproved, wrong purpose or conflict silently resolved by convenience/latest/equal amounts |
| Security identity | Stable securityId plus effective ticker, exchange, instrument/class and currency mappings at observation time | Missing mapping, ticker reuse, cross-ticker contamination or future mapping |
| Price meaning | Explicit close/last/reference/bid/ask/other field, session state, market timezone, observed trading timestamp/date; no field substitutions | Last/ref/adjusted close treated as raw close without approved semantic conversion |
| Adjustments | RAW/ADJUSTED basis, adjustment/factor version and corporate-action knowledge boundary; shares population aligned with market-cap calculations | Mixed raw/adjusted series, unknown split/rights/dividend factors, future-factor leakage |
| Unit/currency | Lossless decimals; declared quote multiplier, currency and volume/share units; explicit conversion formula/rate/time/source | Guessing VND versus thousands VND, share versus lot, missing versus zero |
| Time | Distinct observation/session, publication/provider-receipt, retrieved/ingested, source-revision-known-at and analysis cutoff | Retrieval timestamp is used to freshen old source observations; future receipt/event or unknown required time boundary |
| Provenance/raw | Immutable sanitized request inventory, endpoint/mode/parameters, response status, retrieval time, raw payload path/hash, exact source cell pointer and normalized-to-raw lineage | Normalized rows or hash alone survive but actual required raw bytes/replay equivalent do not |
| Schema/version | Provider schema fingerprint, template/codes/order, adapter and normalizer versions; failed captures quarantined | Schema drift, incompatible field/code changes or rejected cells admitted silently |
| Freshness | Preapproved per-purpose/session/delay policy and exchange calendar; independently recomputable eligible-until and reason per required observation | Missing policy/threshold ownership, UNKNOWN/STALE, unsupported halt/suspension/no-trade handling, unapproved fallback |
| Missing/conflicts | Required coverage plan; zero only when explicitly a valid zero for that field; reasoned no-trade status; typed missing/conflicting observations | Missing price becomes0, missing bar becomes zero volume, partial universe silently becomes complete ranking |
| Corporate actions | Bind effective/known-at adjustment facts and share-count definitions; keep portfolio events/ledger ownership separate | Market refresh rewrites transaction/cash/cost basis or double-counts a corporate action |
| Snapshot/replay | Stable immutable marketSnapshotId/content hash, observation/source membership, transformation/calendar/adjustment/policy pins and deterministic replay | Re-fetching today's values is offered as reproduction of yesterday's snapshot, or mutable latest pointer substitutes for pins |
| Capability qualification | Retained dated real-source sample(s) sufficient for supported source/semantic coverage plus positive/negative/schema-drift/replay tests and independent review | Only mocks/parser tests exist, all real samples were deleted, or source coverage is claimed beyond evidence |

No numeric freshness threshold is invented here. Ownership/effective dates must be approved prospectively. Provider credentials must not enter logs/manifests. Irreplaceable raw market response and final immutable snapshot records are replay dependencies, not disposable OCR/render intermediates. Where retention is unavailable, an explicitly approved equivalent must reproduce exactly; otherwise the source/use case is unsupported. Retaining a historical raw sample proves capability for a version, not freshness for current analysis.

A certificate may be requalified when source/schema/adapter/calendar/rights change. A provider outage creates an operational availability finding; it does not rewrite an old initialization event. Without eligible current observations it still blocks affected live analysis. This review neither certifies the current capability nor fetches any sample.
