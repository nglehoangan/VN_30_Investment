# Decision Snapshot envelope — proposed vNext

Existing DecisionArtifact/scorecard/portfolio lineage and immutable body hashes are useful foundations; they are not discarded. The new envelope makes the full multi-domain binding explicit and enforceable instead of assuming an opaque source/version string proves market replay.

Freeze at minimum:

| Fields | Required binding |
| --- | --- |
| decisionId, decisionTimestamp, requestId, mode, decisionAsOf, systemKnownAt | Trusted clock and causal ordering; live versus historical/backtest explicit |
| initializationSnapshotId / acceptanceHash | Approved durable initialization manifest and capability certificate version |
| universeSnapshotId, sectorSnapshotId | Effective identity/membership/sector master, including full universe and eligibility/exclusions |
| fundamentalSnapshotId, qualification/disposition/exception hashes | Exact selected accounting facts, periods/scopes, revisions, owner exception ACTIVE for TCX and MBB quarantine; no current qualification manufactured into PIT |
| marketSnapshotId, marketGateProofId/hash | Actual price/volume/required observation set, raw payload/source memberships, semantics/units, session/calendar/adjustment/freshness policies and eligibility at consumption |
| analysisSnapshotId, scorecardId, rankingId where applicable | Actual model evidence and output membership; no rankings generated by this review |
| portfolioSnapshotId, portfolioAsOf, ledgerWatermark, reconciliation, priceVersion | Current quantities/cash/costs and coherent valuation source from the frozen market batch; no market-driven ledger writes |
| policyVersion, PolicyB partition hash, scoringModelVersion, decisionEngineVersion | Full method/software/normalizer/schema hashes and effective/known-at governance records, not human-readable version labels alone |
| source hashes, normalized observation/transform hashes, snapshot content hashes | Stored replay dependencies under approved retention; actual bytes or qualified deterministic equivalent, not SHA-only promises |
| freshness status/proof, assessedAt, eligibleUntil, per-input reasons, unresolved exceptions | Recompute then-current authorization; do not assign a permanent LIVE_READY bit to historical decisions |

The logical lifecycle is Data Initialization → Market Data Refresh → Analysis → Portfolio Snapshot → Decision → Decision Snapshot. Implement a final candidate decision plus atomic snapshot binding/publication: if the seal or any final guard fails, no actionable recommendation is published. Require matching market IDs/bases across score/valuation and portfolio context or an explicit approved alignment; a refreshed quote after analysis normally requires rebuilding affected inputs. A ledger-watermark change requires portfolio recapture and affected decision re-evaluation.

Persist append-only/versioned envelopes with referential/body-hash integrity and enforce completeness in repositories/application commands, including cached-result reads. Do not migrate old accepted decisions into vNext by inventing missing source IDs or data. Legacy artifacts retain their versioned replay path; an unqualified historical raw-source gap remains disclosed. Re-fetching new prices cannot repair a missing historic snapshot.

Proposal of logical entities does not require one physical table per entity. An additive versioned storage design should reuse existing trusted source/import, fundamental/portfolio snapshot and methodology infrastructure where semantics match, and add market/initialization/decision bindings where they do not. No schema migration, new decision or snapshot is performed here.
