# Retained certificate body format

`certificateReference` identifies a separate retained **body file**, not an envelope containing its own digest. Its bytes must be exactly `canonicalJson(body)`, with no trailing newline. `body` contains every StructuredCertificate property except `certificateHash`. `certificateHash = SHA256(canonicalJson(body))`. The in-memory envelope is `{...body, certificateHash}`. The source binding for that body path must have the same SHA256. This prevents circular hashing and binds admission to the exact retained review record. The candidate ID, raw provider hash and metric must match independently; all required attestation flags, dimensions, calendar, revision and zero checks still apply.

The positive verifier case uses synthetic trusted input bindings solely to exercise the domain contract. It does not issue a production certificate or qualify any actual provider record. Physical body retention is the loader's responsibility; pure domain input bindings are a trusted ingestion boundary.

No such independently reviewed exact-record bodies exist in the retained production input. The loader therefore supplies zero certificates, and STRUCTURED_CERTIFICATION_REPORT.json records noncertification reasons. The implementation does not turn provider labels, endpoint agreement, accounting identities alone, or a self-generated file into statement/scope/currency/revision evidence. No production certificate was manufactured. Future real certificate ingestion and reviewer authorization need separate retained documentary attestations before promotion; the present closure explicitly uses the permitted noncertification outcome.
