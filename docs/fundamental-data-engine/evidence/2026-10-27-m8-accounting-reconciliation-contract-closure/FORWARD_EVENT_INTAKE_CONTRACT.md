# Forward event intake contract

Assessment date: 2026-10-27 (Asia/Ho_Chi_Minh). Phase 1 design/evidence closure only. Owner approved the prior architecture assessment as baseline v1.0 in the current task; this is not authenticated source/identity acceptance or Phase 2 authorization. Original baselines and sealed evidence remain unchanged. SOURCE_REFERENCES.json pins inspected files; JSON Pointers below address those pinned bytes.

Proposed workflow, not an importer implementation:

1. Retain immutable original receipt plus manifest (provider/account pseudonymous perimeter ID, request/file ID, hash, row/pointer, original stable event ID, retrieval time, effective/trade/settlement dates and precision, knowledge witness). An export date is not historical knowledge.
2. Stage candidate classification. BUY/SELL are trade-date quantity and claim events; paired settlement changes cash only. Broker securities posting rows and trade execution rows are corroborating representations, not two purchases. DIVIDEND_CASH only for income not already represented as a claim; claim settlements use proposed explicit extension. Interest/fee/liability unsupported semantics are quarantined, never mislabelled CASH_DEPOSIT.
3. Resolve exact source, account scope, security identity, action identity and accepted purpose independently. Missing identifiers/known-cutoff/action terms block affected candidate. Local no-login does not constitute authenticated acceptance.
4. Anti-pre-opening check: retain opening instant2026-10-08T11:38:01.705Z and source watermark. Pre-opening trades17 and historic credits stay research evidence. Same-day date-only events cannot be classified after opening without timing witness. Old trade settlement after opening must use an explicitly recognized opening obligation and reviewed linkage, not repost old purchase/SELL.
5. Idempotency checks on transaction ID, key, provider-event identity and source reference; economic duplicate registry links overlapping statement/capture representations. Identical retry returns old result; conflicting payload fails. Multi-event allocation requires unique typed component keys and conserved source totals. Existing candidate.ts rejects reused source reference: new component-key design must preserve strong economic dedup, not weaken it.
6. Independent classification/reconciliation review, then scoped authorized posting. Prepare exact proposed facts/legs and expected before/after states. No current operational acceptance mechanism is available merely from this task approval.
7. Expected-revision CAS plus authoritative history read and validation within one DB transaction. Revalidate every past/future affected boundary, no-margin and obligation constraints; atomic correction groups use existing same-effective-time restriction. Create immutable transaction/ordered legs, claim allocations, source-consumption registry, idempotency outcome and governance audit together. Crash/failure rolls all back; conflicting sessions fail/retry with fresh read, not last-write-wins.
8. Projection is derived cache, not truth. Existing completePost can report committed-but-projection-failed; retry projection only, never post again. Compare ledger watermark and evidence versions before exposing results.
9. Reconcile to dated broker cash, positions, pending availability, claims and debt; exact differences retained. Unresolved economic completeness blocks accepted current holdings/NAV or affected capability. Preserve ordinary read-only observations with warnings.
