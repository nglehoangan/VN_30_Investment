# VN30 scoring publication and retention

Use the [single-ticker contract](../vn30-rollout-orchestrator/references/single-ticker-contract.md). Each ticker retains its own route, approvals, result and readback. Keep scratch and failed diagnostics in one private temporary directory per execution. Persist only artifacts needed for decisions, recovery or replay.

Follow assessment → two reviews → prepare → exact CIO approval → authorized check → score → separate publication approval → website publication → website readback → safe cleanup. A SQLite publication envelope, a renderer test or a completed scoring command alone does not establish successful website readback. Verify HTTP on the intended website, the scorecard ID and cutoff, exact publication hash, coverage/interval/N/R presentation, version and allocation restrictions. Display previous published versions and reassessment tracking independently of draft research.

For an existing research closure, a blocked `prepare`, or an exact execution approval, read [formal scoring handoff](references/formal-scoring-handoff.md). Start at the first unverified layer using the current receipts.

Identify the intended deployment target and existing materialization and publication route early. Bind the read-only publication decision to the exact scorecard, dataset, methodology and review identities. Record local preview, isolated publication and target website readback as separate states. When HTTP validation stalls, report the observed failure and any targeted renderer or type checks that completed.

| Class | Retain |
| --- | --- |
| KEEP_CANONICAL | Published artifact, publication manifest, receipt, website readback and Future Evidence Register |
| KEEP_ARCHIVE | Unique source, dataset, methodology/executable, assessment and review pins, owner approvals, preflight, execution evidence and historical versions |
| PRUNE_CANDIDATE | Explicitly listed, redundant and unreferenced working files whose bytes are known |

Use [the cleanup operation](../../tools/maintenance/scoring_cleanup.py) and its [operating guide](../../tools/maintenance/SCORING_CLEANUP.md). Build an explicit SHA-256 allowlist. Inventory and classify first. Resolve references by path/basename and digest, including stored lineage, before treating a file as disposable. Retain unclear or undiscoverable dependencies. Dry-run is the default. After matching website readback, show the exact dry-run plan to the owner and obtain approval for its digest before apply. Copy and verify the rollback archive before removing any file. Use rollback for a mistaken or interrupted apply. Preserve Git history and approvals throughout.

During an execution, remove clearly disposable scratch generated by that execution after retaining any unique diagnostics or replay dependencies. Keep the isolated score store until the canonical artifact and receipt have been verified and retained. Repository artifact pruning follows the governed cleanup operation above.

For Prepare, valuation or decision feasibility audits, retain the final scoped packet and its required immutable evidence. Apply the existing scratch cleanup and publication gates in this skill. A [feasibility verdict](../../docs/03%20SCORING/STRUCTURAL_EVALUATION_GAPS_v1.0.md) grants no publication or action authority.

## Public-data assessment routes

Use the approved public-data baseline in the assessment and formal handoff. Any changed executable requires exact separate authority before formal scoring; existing publication gates apply. Follow the [Approved Baseline v1.0 and stopping rules](../../docs/03%20SCORING/PUBLIC_DATA_PROXY_SPECIFICATION_23_RUBRICS.md#evidence-discovery-workflow-and-stopping-rule).

## Governed category rollout

Category execution parameters use one ticker with `category`, `cutoff`, `methodologyVersion`, `priorAcceptedCategories` and `executionScope`. Resolve the cutoff and category from the approved candidate. Preserve prior accepted categories on identical inputs.

Retain approved methodology, exact owner records, final assessments and results, source lineage, executable identity and replay inputs, tests and acceptance records, and publication authority. Dispose of redundant temporary files only under the existing retention rules. Research closure carries no production publication authority.

### Approved Financial Health A/B routes

Retain the owner-approved route order and ceilings, both route diagnostics, shared financial inputs and exact research replay. Do not replace sealed predecessor records or infer formal publication authority.

For FH-LIQ and FH-STRESS, apply the [approved v1.2 amendment](../../docs/03%20SCORING/WP2_FINANCIAL_HEALTH_ANALYST_RISK_v1.2.json) to one ticker and the requested Financial Health periods. Method B retains the canonical direct bands and takes priority. For eligible detail gaps, Method A assesses a distinct public-data risk profile, capped at 3/4 for FH-LIQ and 4/5 for FH-STRESS. Reuse the qualified source-bound financial product and sector normalization, including bank and property conventions. Preserve observed facts, calculations, estimates and scenario assumptions separately. Avoid repeat discovery.

Record an explicit analyst band or N/R before validation, with evidence for the selected conclusion, adjacent-band rationale, counterevidence disposition and limitations. Review whether each unresolved dependency affects that band. Never infer points from a ratio or treat unverified resources or actions as certain. Record the five confidence dimensions independently of points, and enforce the existing freshness, invalidation and historical eligibility checks. Carry method and band semantics through research consumers with no formal gate credit or assumed cross-route cardinal equivalence. Keep genuine N/R distinct from outside scope.
